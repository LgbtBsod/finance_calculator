# Изменения

## 3.1.1

Фикс: запуск через `run.bat`/`run.sh` мог падать с `ModuleNotFoundError: No
module named 'flet'`, хотя `scripts/launch.py` вроде бы «синхронизировал
зависимости».

Причина: штамп `logs/.dep_sync` («зависимости ставили недавно, пропускаем
pip») — это просто файл со временем, он не знает, какой venv был активен,
когда синхронизация прошла. Если `run.bat` создавал `venv/` заново с нуля
(папка пропала / новая машина / OneDrive не досинхронизировал), а старый
штамп ещё не протух по TTL (24ч), зависимости молча пропускались, и
`main.py` падал на пустом venv.

- `_deps_fresh()` теперь дополнительно проверяет, что `flet`/`flet_web`/
  `certifi`/`packaging`/`work_calendar` реально видны текущему интерпретатору
  (`importlib.util.find_spec`) — штамп сам по себе больше не решает.
- Если после явной попытки установки обязательные модули всё равно не
  видны — `launch.py` завершается понятной ошибкой с командой для ручной
  установки, вместо тихого запуска `main.py` в гарантированный крэш.

## 3.1.0

Внутренний рефакторинг: `database.py` (1109 строк, один класс) → слоёный пакет
`db/`. Поведение байт-в-байт не менялось (проверено на реальной БД: прямые
чтения и агрегации идентичны). 333 теста.

- **`db/engine.py`** — «ядро БД»: соединение, транзакция, backup, **read-through
  кэш** горячих целотабличных чтений (`get_settings_bundle`, `get_expense_groups`)
  с инвалидацией по write-пути и защитой от гонки поколением кэша.
- **`db/schema.py`** / **`db/migrations.py`** — DDL и миграции отдельно от CRUD.
- **`db/query.py`** — `RECURRING_WHERE`, `period_overrides`, `_UNSET` и новый
  `build_update` (общий сборщик частичного UPDATE вместо двух ручных).
- **`db/rows.py`** — мапперы строк; **`db/repositories/*`** — CRUD по сущностям
  (9 репозиториев); **`db/facade.py`** — `Database` (поверхность 1-в-1 со старым
  `DatabaseManager`, alias сохранён).
- `test_db_package.py`: golden-snapshot схемы (байт-в-байт), точный текст SQL
  `build_update`, поведение кэша, целостность колонок undo-таблиц.

## 3.0.1

Внутренний рефакторинг архитектуры — поведение не меняется, 320 тестов зелёные.

- `modules/calculator` отдаёт `SalaryBreakdown` / `BalanceResult` (frozen
  dataclass) сквозь ядро как есть; убран `_breakdown_to_dict` — ручная
  stringly-typed таблица «поле → dict» на каждый вызов. Потребитель (`finance`)
  читает поля по имени.
- `modules/db` стал декларативным: таблицы `_READS` / `_ADDS` / `_UNDO_DELETES`
  описывают «действие → метод БД → затрагиваемые сущности `db:changed`» в одном
  месте; ~55 строк однотипного форвардинга заменены фабриками хендлеров.

## 3.0.0

Крупный релиз: переход с FastAPI+React на standalone Flet, модульная
архитектура через ядро, редизайн под SAP Horizon и большой пласт правок по
аудиту.

### Архитектура
- Standalone Flet вместо FastAPI+React; модульное ядро (`core/` + `modules/`),
  модули общаются только через Kernel, изоляция проверяется AST-тестом.
- `services.FinanceService` — единственный фасад GUI поверх ядра.
- Единый источник настроек `config.SETTINGS` (seed + чтение + запись).
- SSOT названий месяцев; порядок init/shutdown ядра — топосорт по `requires`.
- Потокобезопасность ядра (per-thread контекст запроса).

### Зарплата и расчёты
- Зарплата — сущность «доход» (`income.kind='salary'`): оклад/КЕФ/метод/
  пропорции на самой записи; **несколько работ** суммируются.
- Отпуск урезает оклад пропорционально отработанным дням (ТК РФ) для всех
  методов; граница половины месяца — по дню отсечения аванса.
- Прогрессивный НДФЛ 2025 (опция) — предельный налог месяца по годовому
  накоплению.
- Плановый платёж по долгу вычитается только за «живые» месяцы.

### Данные и надёжность
- БД в подпапке `db/` + автомиграция со старой раскладки.
- Отмена удаления (undo) вместо безвозвратного DELETE.
- Сумма повтора на один месяц (`period_overrides`).
- Строгий формат `recurring_until`; `backup_to` закрывает соединение.
- Диапазонные запросы к календарю вместо `LIKE` (индекс).
- Проекция повторяющихся строк помечается `projected`; правка/удаление
  проекции безопасны.
- Ошибка на экране не роняет приложение (error boundary во вью).

### Интерфейс
- Тема **SAP Horizon** (Morning / Evening) — палитра 1-в-1 из
  `@sap-theming/theming-base-content`, радиусы и тени Horizon.
- Fiori-стиль навигации; поля/кнопки/чипы/пустые состояния переоформлены.
- Сохранение позиции прокрутки при перестройке экрана.
- «Доходы» — отдельная форма зарплаты; «Настройки» без окладных полей.

### Аналитика и экспорт
- Тренд доход/расходы (кэшфлоу) с «чистыми» по месяцам.
- «Изменение к прошлому месяцу» по категориям.
- Аналитика «за всё время» с разворотом повторов.
- Экспорт всех записей в CSV (Excel/Google Таблицы).
- Предупреждение о превышении лимита группы на «Балансе».

### Сборка и обновления
- Сборка на CI под три ОС, `version.txt` сверяется с тегом.
- Апдейтер сверяет SHA256 бинарника с суммой из релиза, бэкапит `db/`.
- `requirements.txt` — единый список зависимостей, flet пиним точно.
- `scripts/launch.py` — гейт синхронизации зависимостей (раз в сутки) + таймаут.

# 🏦 Личный финансовый калькулятор

Десктопное приложение для планирования личного бюджета по производственному
календарю РФ: зарплата с авансом и расчётом по рабочим дням, отпускные по
ТК РФ, расходы и доходы (в т.ч. повторяющиеся), группы с лимитами, дни
рождения, долги, аналитика и экспорт.

Интерфейс — [Flet](https://flet.dev) (локальный сервер + вкладка браузера),
тема — **SAP Horizon** (светлая «Morning» / тёмная «Evening»). Данные — один
локальный SQLite-файл `db/budget.db` рядом с приложением, никуда не уходят.

## 🚀 Запуск из исходников

```bash
run.bat        # Windows
./run.sh       # Linux / macOS
```

Скрипт создаёт venv, синхронизирует зависимости (не чаще раза в сутки),
проверяет обновления и запускает `python main.py`. Откроется вкладка браузера
на `http://localhost:8420`.

Вручную:

```bash
python -m venv venv && venv\Scripts\activate     # source venv/bin/activate — *nix
pip install -r requirements.txt
python main.py                                    # --version / --help / --port N
```

## 📦 Сборка standalone-версии (.exe)

```bash
python build.py --clean
```

Результат — `dist/FinanceCalculator.exe` (Windows) / `dist/FinanceCalculator`
(Linux, macOS). Папка `db/` (БД пользователя), `logs/` и `version.txt` живут
рядом с бинарником и переживают авто-обновление. БД из старой плоской раскладки
(`budget.db` рядом с exe) переносится в `db/` при первом запуске.

## 🔄 Обновления

Собранная версия проверяет GitHub Releases при запуске (отключается в
«Настройки → Обновления»). Установка: бэкап `db/`, сверка SHA256 скачанного
бинарника с `<asset>.sha256` из релиза, подмена на месте, откат при ошибке.
Релиз выпускается пушем тега `vX.Y.Z` — GitHub Actions
([`.github/workflows/build.yml`](.github/workflows/build.yml)) прогоняет тесты,
собирает три ОС и прикладывает бинарники + суммы к релизу.

## 📊 Возможности

- **Зарплата** — сущность «доход» типа «Зарплата»: оклад, КЕФ, метод
  распределения аванс/выплата (пропорционально / свои пропорции / по рабочим
  дням производственного календаря РФ). Несколько записей = несколько работ,
  суммируются. Отпуск урезает оклад пропорционально отработанным дням (ТК РФ),
  отпускные — отдельной суммой. НДФЛ — плоский или прогрессивная шкала 2025.
- **Баланс** по половинам месяца: к выплате, прочий доход, расходы, платёж по
  долгу, остаток/дефицит; даты выплат с переносом с выходных.
- **Расходы / доходы** — разовые и повторяющиеся (проекция вперёд до даты
  окончания); сумму повтора можно переопределить на один месяц; удаление
  обратимо (снекбар «Отменить»).
- **Группы** расходов с месячными лимитами и предупреждением о превышении.
- **Отпускные** с диапазоном дней. **Дни рождения** — напоминания и
  авто-расходы на подарки. **Долги** — платежи, плановый ежемесячный платёж,
  прогноз погашения.
- **Аналитика** — тренд доход/расходы (кэшфлоу), изменение к прошлому месяцу,
  расходы по категориям, экспорт всех записей в CSV.
- **Резервное копирование** БД в один клик.

## 🗂️ Архитектура (кратко)

Ядро + модули: `core/` (Kernel + KernelView, два канала `request`/`emit`),
`modules/` (`db` — единственный с SQL, `cache`, `calendar`, `calculator`,
`birthdays`, `finance`, `updater`) — общаются только через ядро, изоляция
проверяется AST-тестом. `services.FinanceService` — тонкий фасад GUI.
Легаси-слой (`config`, `models`, `database`, `calculator`, `prod_calendar`,
`updater`) — kernel-agnostic, обёрнут модулями.

Подробнее — [ARCHITECTURE.md](ARCHITECTURE.md).
